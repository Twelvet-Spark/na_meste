# Мониторинг камер и присутствия сотрудников

**Quick English runbook:** [RUNBOOK.md](RUNBOOK.md) — setup, camera connection lifecycle, AI/data flow, configuration, and operational limitations.

Локальное web-приложение:

- **Камеры**: отдельные IP-камеры и каналы регистраторов **Dahua** по RTSP, живое превью (MJPEG)
- **AI**: обнаружение людей (D-FINE-S), локальный трекинг, распознавание лиц
  сотрудников (YuNet + AuraFace/ArcFace), события прохода и проверяемые рабочие интервалы
- **Telegram**: уведомления о подтверждённых входах/выходах и
  переходах глобальной личности между камерами после подтверждения записи в БД
- **Межкамерный трекинг**: сопоставление global_id между камерами
  (Person Re-ID OSNet + composite matching + топология); возможны лишние или ошибочные ID
- **Журнал людей**: отдельный визит каждого наблюдённого трека, включая неизвестных,
  сидящих людей и первое наблюдение; необязательный Re-ID не определяет его наличие
- **Разметка сцены**: видимый пол, предметы, измеренный прямоугольник и отдельная
  линия входа; локальные CPU-подсказки MobileSAM требуют проверки оператором

RTSP-модуль не зависит от AI; AI получает кадры из его буфера.

Учёт собирает появления сотрудников на всех камерах с включённым «Учёт времени».
Разметка прохода необязательна и уточняет перерывы; отдельного ввода в эксплуатацию нет.
Приложение не имеет аутентификации: только localhost, доверенная LAN/VPN,
без публикации в интернете. [Правила учёта и приёмки](ATTENDANCE.md).

## Архитектура

```text
Dahua NVR
    │  RTSP (over TCP)
    ▼
FFmpeg (subprocess, rawvideo bgr24)
    │
    ▼
RTSP Reader (фоновый поток, авто-реконнект)
    │
    ├── MJPEG preview → браузер (PREVIEW_FPS, по умолчанию 10 FPS)
    │
    └── FrameBuffer (один последний неизменяемый кадр)
            │
            ▼
       AI Worker (1 владелец, пакеты разных камер по ближайшему сроку)
            │
            ├── D-FINE-S COCO Person Detection (проверенный ONNX bundle)
            ├── Локальные Kalman/Hungarian-треки (предсказания не наблюдения)
            ├── YuNet Detection + AuraFace Embedding
            ├── Employee Recognition (обычный режим / строгий ATTENDANCE_*)
            ├── HumanJournal → локальные визиты / подтверждённые ссылки UUID
            ├── OSNet → галерея внешности сотрудников текущего дня
            └── Появления + проходы → PresenceRecorder → SQLite → часы
                    ▼
              Web UI + Telegram-группа
```

## Стек

- Python 3.11+, FastAPI, SQLAlchemy, SQLite (WAL)
- FFmpeg / ffprobe (RTSP over TCP, декодирование)
- OpenCV, numpy
- ONNX Runtime GPU/CPU, YuNet, AuraFace, OSNet AIN; SciPy и scikit-image
- HTML/CSS/vanilla JS — без frontend-фреймворков

## Установка

### 1. FFmpeg

**Windows**

```bash
winget install --id=Gyan.FFmpeg -e
```

После установки перезапустите терминал. Альтернатива: сборка с
<https://www.gyan.dev/ffmpeg/builds/> в папку `bin/` проекта.

**macOS**: `brew install ffmpeg`  **Ubuntu**: `sudo apt install -y ffmpeg`

Текущие FFmpeg/ffprobe-операции (живой RTSP, пробы, запись и просмотр)
требуют Windows 10/11 и Windows Job containment. Установка FFmpeg на
macOS/Linux сама по себе не включает их: небезопасного fallback без изоляции
нет. Интерфейс и ручная работа с учётом отделены от доступности медиа.

### 2. Python-зависимости

```bash
python -m venv .venv
.venv\Scripts\activate           # Windows
source .venv/bin/activate        # macOS / Linux
python -m pip install -r requirements.txt
```

**Важно (GPU)**: не оставляйте CPU- и GPU-дистрибутивы `onnxruntime` вместе:
они предоставляют один Python-модуль. PyTorch нужен только отдельному окружению
экспорта моделей, не серверу. Для NVIDIA после установки зависимостей:

```bash
python -m pip uninstall -y onnxruntime
python -m pip install --no-deps --force-reinstall onnxruntime-gpu
```

Для CPU удалите оба дистрибутива, установите только `onnxruntime` и выберите
`AI_DEVICE=cpu`. CPU подходит для ручной работы/разработки, но не доказывает
готовность автоматического учёта на целевой установке.

### 3. CUDA (Windows, опционально)

CUDA/cuDNN и драйвер NVIDIA должны соответствовать **конкретной установленной
сборке** ONNX Runtime, включая источник её пакета. CUDA 12 и 13, как и разные
major-версии cuDNN, не взаимозаменяемы. Номер ORT сам по себе не определяет
major CUDA для всех вариантов пакета. Сверяйтесь с
[официальной таблицей CUDA EP](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#requirements)
и инструкцией выбранного пакета.

Официальная документация предлагает установку runtime-зависимостей через extras:

```bash
python -m pip install "onnxruntime-gpu[cuda,cudnn]"
```

Используйте ту же выбранную версию/источник ORT, что и для самого GPU-пакета;
не смешивайте случайные колёса CUDA 12/13. Это не установка драйвера NVIDIA.
Для сборки без этих extras следуйте инструкции её поставщика.

Windows-поиск DLL приложения: `CUDA_DLL_PATH` → `bin/cuda/` проекта →
NVIDIA-пакеты текущего venv → поддерживаемый соседний torch →
системные каталоги CUDA/cuDNN. Наличие каталога или
`CUDAExecutionProvider` в списке доступных провайдеров не доказывает успешный
инференс. Смотрите фактические провайдеры загруженных моделей в `/debug`
и стартовый `AI Provider`. При проблемах возможен CPU fallback; ошибка загрузки
модели может отключить live AI или загрузку фото, не всё приложение.

### 4. Проверенный коммерчески разрешённый набор моделей

Сервер читает только `AI_MODEL_MANIFEST=models/store-v1/manifest.json`.
Во время запуска модели не скачиваются. Подготовьте их отдельным окружением:

```bat
py -m venv .model-build
.model-build\Scripts\python.exe -m pip install -r tools\model_build_requirements.txt
.model-build\Scripts\python.exe tools\prepare_models.py --output models/store-v1 --device cpu
```

Для проверки CUDA и допустимых FP16-вариантов используйте `--device cuda`.
Ошибочная конверсия не заменяет рабочий набор; вместо неё остаётся полная FP32-модель.
Проверяются реальные N=1/4 и все 17 векторов, а не только объявленные размеры.
Профиль CUDA проверяет исполнение тяжёлых узлов; список доступных провайдеров этого не доказывает.

| Назначение | Выбранный источник | Грант |
|---|---|---|
| Люди | [D-FINE-S, только COCO](https://github.com/Peterande/D-FINE) | Apache-2.0 |
| Лица | [OpenCV YuNet 2026may](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet) | MIT |
| Векторы лиц | [AuraFace-v1, только glintr100.onnx](https://huggingface.co/fal/AuraFace-v1) | Apache-2.0 |
| Внешность тела | [OSNet AIN x1.0 автора](https://huggingface.co/kaiyangzhou/osnet) | MIT |
| Подсказки контуров | [MobileSAM vit_t](https://github.com/ChaoningZhang/MobileSAM) | Apache-2.0 |

Точные исходные ревизии, SHA256, правила предобработки, активная точность и лицензии
сохраняются вместе с набором. Это гранты авторов, не независимая гарантия прав на
обучающие данные. `YOLO_MODEL`, `INSIGHTFACE_MODEL`, `INSIGHTFACE_ROOT`, `REID_MODEL`
больше не выбирают веса. Пользовательский `.env` и прежние файлы моделей не удаляются.
Некоммерческие buffalo/antelope/SCRFD и чужой неподтверждённый ONNX не подставляются.

При переходе на модель сначала сделайте резервную копию БД. Миграция operator-v4
добавляет происхождение каждого образца, не меняя таблицы учёта. Совместимые векторы
остаются неизменными; прочие пересчитываются только из действительных сохранённых
JPEG 112×112. Исходные загруженные фотографии не хранились. Образцы без подходящего
изображения сохраняются, но не участвуют в поиске; интерфейс показывает необходимость
новых фотографий и различает сохранённое/пригодное количество. Повторный совместимый
запуск не меняет галерею.

`AI_ENABLED=false` отключает live AI, но не отдельный движок фото.
Отсутствие лиц/галереи не отключает обнаружение людей. CPU поддерживается для
корректности, но не подтверждает целевую многокамерную производительность.

## Запуск

Из корня проекта используйте Python выбранного venv:

```bash
python main.py
```

Windows: `start_server.bat` выбирает `.venv`, затем `venv`, и возвращает
код завершения сервера (без окружения — 1). Для новой установки создайте
`.env` из `.env.example`, не перезаписывая существующий файл.
Открыть: **<http://localhost:8000>** (если `APP_PORT` не изменён; API docs — `/docs`).
При запуске приложение автоматически запускает ридеры всех сохранённых
включённых камер; подключение асинхронное, с переподключением при сбоях.
Повторно сохранять каждую камеру не нужно. Проверка подключения и открытие
превью сами по себе ридер не запускают. Ручная видеозапись не возобновляется.

Запускайте один процесс приложения, без reload и нескольких uvicorn workers.
`run_server_task.bat` создаёт каталог `data` для `data/app_run.log`, один раз
при своём запуске читает `APP_PORT` через Settings без открытия БД, ждёт при
занятом порте и повторяет запуск через 5 с после завершения сервера.
После изменения `APP_PORT` перезапустите и обёртку, не только сервер.
Допустима **только одна копия обёртки**: проверка
порта не является блокировкой и не доказывает, что порт занят именно этим приложением.
Перед обслуживанием остановите и обёртку, и сервер, иначе сервер запустится снова.

## Что видно в интерфейсе

Навигация: «Камеры» (`/`), «Сотрудники» (`/employees`), «Рабочее время»
(`/presence`), «Записи» (`/recordings`), «Настройки» (`/settings`),
«Диагностика» (`/debug`); «Журнал людей» (`/global`) — вторичная ссылка.
На широком экране меню находится слева, на узком открывается кнопкой «Меню».

- **Камеры** (дашборд): превью, состояние, адрес/канал/поток и счётчики людей;
  «Добавить устройство» открывает мастер камеры или регистратора Dahua.
- **Камера**: живое видео + bounding boxes поверх (зелёный — сотрудник с именем
  и уверенностью, красный — Unknown, жёлтый пунктир — распознаётся); отдельно
  параметры архива и подключения, редактор сцены/масштаба и отдельная линия входа.
- **Сотрудники**: поиск по фамилии, имени и внешнему ID, фильтры по рабочему
  месту и активности; в строках видны принятые фото и готовность карточки.
  «Добавить сотрудника» открывает отдельную страницу `/employees/new`:
  фамилия, имя, необязательные рабочие места и черновик из 1–15 фотографий.
  Выбор файлов не начинает загрузку. Создание и замена итогового набора
  атомарны: ошибка одного файла ничего не сохраняет. В карточке разделы
  «Данные», «Фотографии», «Рабочее время», «История», явные сохранение/отмена
  фото и восстановление черновика при конфликте версий. Нечёткие лица,
  низкая уверенность детекции, неверное выравнивание, неоднозначные фото и
  совпадение с другим активным сотрудником отклоняются, а не дают лишь предупреждение.
  [Порядок работы и сохранность истории](ATTENDANCE.md#сотрудники-и-рабочие-места).
  Старые карточки без имени/фамилии или допустимого набора фото показывают
  подсказку для исправления: дополните данные и фотографии, сохранив ID и историю.
- **Рабочее время**: подтверждённые входы/выходы, интервалы, проверка и отчёты.
- **Настройки**: параметры следующего запуска, активные и ожидающие значения,
  состояние моделей/галереи/журнала и частота анализа камер;
  управление необязательными рабочими местами без удаления назначений и истории.
- **Диагностика**: фактические провайдеры AI, версии галереи, очередь журнала,
  этапы обработки и задержки камер, CPU-подсказки, запись и безопасный отчёт поддержки.
- **Журнал людей**: вкладка «Наблюдения» открывает визиты по UUID; старые целочисленные
  `/global/{id}` и межкамерный архив сохранены. Наблюдения не являются рабочими часами.

Фото принимается только с одним лицом: меньшая сторона рамки не ниже
`max(80, FACE_MIN_SIZE)` px, уверенность детекции ≥0.80, дисперсия Лапласиана
выровненного лица ≥20 и корректное выравнивание 112×112.
Рабочие места — необязательные метки (можно выбрать несколько), не расписание,
часовой пояс или разрешение автоматического учёта. Создание доступно и рядом
с выбором места в форме сотрудника; управление — в `/settings`. Архивную метку
можно оставить или снять у уже назначенного сотрудника, но нельзя назначить заново.

## Подключение камеры или регистратора Dahua

1. Нажмите «Добавить устройство», выберите «Камера Dahua» или «Регистратор Dahua».
2. Укажите **только IP/имя устройства**, без URL, пути, логина и порта в адресе.
   IPv6 поддерживается с квадратными скобками и без них. RTSP-порт по умолчанию
   554; логин и пароль задаются отдельно. При редактировании пустой пароль
   оставляет сохранённый секрет, API его не возвращает.
3. Проверьте живое видео выбранного канала/потока. Камеру можно сохранить
   офлайн и проверить позже; сохранение не запускает видеозапись.
   Включите «Учёт времени» отдельно; разметка прохода необязательна.
4. Для регистратора обнаружьте каналы через CGI или добавьте вручную номера
   **1–64**, названия и основной/дополнительный поток. Отсутствие CGI-разрешения
   не блокирует полезное RTSP-подключение. Все выбранные каналы сохраняются
   одной операцией: дубликат или ошибка отменяет весь набор.
5. В «HTTP и архив регистратора» отдельно задайте HTTP/HTTPS и порт
   (обычно 80/443). Для архива явно укажите фиксированное смещение часов
   устройства от UTC, **−720…840 минут**, и подтвердите его применимость к
   записям. Смещение рабочего места — только подсказка по кнопке, не
   предположение о часах устройства. Автоматической смены часов/DST нет.

Живой RTSP и обнаружение CGI проверяются независимо. Обнаружение названий
не доказывает доступ к записям: поиск и просмотр проверяются отдельно в «Записи».
Локальная запись включается в карточке камеры, только вручную.
CGI использует Digest или Basic только после соответствующего запроса устройства,
тайм-аут 10 секунд и ответ до 1 МиБ; системные прокси и перенаправления не
используются. Сертификат HTTPS проверяется без небезопасного обхода.
Повреждённый ответ при поиске архива, включая недопустимые индексы элементов,
отклоняется с HTTP 502 / `DEVICE_PROTOCOL_ERROR`, а не считается пустым архивом.
Совместимость проверяется на конкретной модели/прошивке: локальный протокольный
стенд не является доказательством работы реального Dahua.

Изменение RTSP-адреса, порта, логина/пароля, канала или потока отключает
прежнюю разметку и требует повторной наладки. Изменение только HTTP/смещения
архива не меняет учёт и историю. Камеру с историей нельзя удалить — отключите
её; одни параметры архива не препятствуют удалению неиспользованной камеры.
При параллельных операциях ридер учитывает порядок транзакций: запоздавшее
создание не возобновляет удалённую камеру, а старое удаление не останавливает
новый источник с тем же ID.

## Локальная видеозапись

В карточке камеры откройте «Локальная запись», задайте 1–1440 минут,
подтвердите политику хранения и нажмите «Начать запись». По умолчанию —
24 часа, это максимальная длительность одного запроса, а не срок хранения.
«Остановить запись» сохраняет проверенный последний неполный фрагмент.
Сохраняется исходное H.264/HEVC-видео без звука отдельным FFmpeg-процессом;
это не запись MJPEG-превью и не источник событий учёта рабочего времени.

`RECORDING_ROOT` по умолчанию — `data/recordings`, относительный путь считается
от корня приложения. Хранение — `RECORDING_RETENTION_DAYS=14`, общий лимит
`RECORDING_MAX_BYTES=150000000000` (150 ГБ), свободный резерв
`RECORDING_MIN_FREE_BYTES=2000000000`. Лимит учитывает активные файлы и кэш;
при нехватке места старые незанятые записи удаляются раньше срока. Если
освободить место безопасно нельзя, запись останавливается с `STORAGE_FULL`.
Время на шкале — приблизительное серверное, не часы экспозиции камеры.

Медиа поддерживается на Windows 10/11 с одним uvicorn worker: эксклюзивная
блокировка каталога и Windows Job не дают второму владельцу менять индекс
и не оставляют FFmpeg после смерти приложения. Ошибка изоляции/хранилища
блокирует медиа с 503, но не карточки сотрудников и ручной учёт. После
перезапуска незавершённые записи становятся прерванными; автоматического
возобновления нет. Смена живого источника или отключение камеры останавливает
запись; изменение только архивного смещения её не останавливает.

## Просмотр видеозаписей

В «Записи» выберите камеру, источник — локальные записи или архив Dahua —
и период не больше 24 часов. Ввод/отображение используют часовой пояс браузера;
API получает явное UTC-смещение. Для Dahua применяется отдельно подтверждённое
фиксированное смещение устройства, без автоматического DST и смены его часов.
Поиск проверяет права архива независимо от живого видео; ошибка доступа,
тайм-аут или неподдерживаемая прошивка не выдаются за пустой архив.

Выберите доступный фрагмент или время на шкале. Видео начинается с выбранного
места и поступает постепенно, без ожидания готового часового файла. Доступен
один преобразователь одновременно; просмотр ограничен часом непрерывной записи.
Кнопки ±10 с, ввод времени и клавиатура шкалы делают новый запрос за пределами
буфера. Через настоящий разрыв перехода нет: следующая запись предлагается
отдельной кнопкой. Скорость — 1×, часы на экране — время записи, не генерации.
После паузы и истечения кэша «Продолжить» открывает сохранённое время, не live.

Нужны FFmpeg/ffprobe и `libx264`; H.264 и HEVC преобразуются в браузерный HLS
без звука, нечётный размер дополняется до чётного. hls.js 1.7.4 поставляется
локально с лицензией Apache-2.0; поддерживается и нативный HLS, иначе показана
ошибка браузера. Кэш ограничен 2 ГБ и входит в общий лимит 150 ГБ. Занятые
файлы не удаляются; нехватка безопасно освобождаемого места останавливает просмотр.
Уход со страницы/смена источника закрывает просмотр, но не ручную запись камеры.

Историческое локальное видео не теряется при смене реквизитов/канала/смещения
камеры; текущий удалённый просмотр при смене параметров отменяется. Ссылка из
камерного события ведёт к его времени; снимки учёта остаются доступны отдельно.
Ручные события не получают камерной ссылки. Видео не запускает распознавание,
не меняет рабочие часы и не поддерживает поиск сотрудников или лиц.

Для всех изменяющих API-запросов передавайте `X-Operator-Request: 1`, включая
создание/закрытие просмотра и ручную запись; это не аутентификация.
Для поиска используйте интервалы `GET /api/recordings/timeline` и их время `from`
или предложенное `next_at`. Создание `POST /api/recordings/playbacks` требует
`camera_id`, `source`, `at` с UTC-смещением и UUID `request_id`; ответ 202,
тот же UUID/набор повторяет результат, другой набор — 409. Состояние читается
по `/api/recordings/playbacks/{id}`, DELETE закрывает просмотр. 429 — занят
единственный преобразователь; 410 — кэш истёк, нужен новый запрос с сохранённого
времени. Пути устройства, пароли и аргументы процессов браузеру не выдаются.

## Операторские настройки и диагностика

`/settings` сохраняет только разрешённые параметры потоков, AI, порогов учёта,
уведомлений, хранения видео и отладочных сообщений. Изменения **не применяются
на лету**: после сохранения видны текущие/ожидающие значения и баннер
«Сохранено. Требуется перезапуск». Выполните обычный перезапуск приложения;
HTTP-команды перезапуска нет. Живые камеры восстанавливаются, ручная запись —
нет. Изменённые пороги требуют повторного ввода учёта в эксплуатацию, не
пересчитывая историю. Смещение рабочего дня доступно только для чтения.

Файл по умолчанию — `data/operator-settings.json`, формат
`{"version":1,"values":{...}}`. `OPERATOR_SETTINGS_PATH` выбирает другой файл
при запуске; относительный путь считается от корня приложения. Приоритет:
**окружение → операторский файл → .env → значения по умолчанию**.
Поля окружения заблокированы. Сброс удаляет только выбранное переопределение.
`.env` и скрипты запуска интерфейс не меняет. Неверный формат или неизвестные
параметры операторского JSON останавливают запуск с безопасным кодом ошибки.
Неизвестные ключи `.env` игнорируются; это не повод считать их действующими.

Сохранение атомарное, с проверкой версии точных байтов файла. При конфликте
409 черновик сохраняется: сначала сверьте серверную версию, затем явно
перенесите черновик и повторите сохранение. Пустое поле нового токена Telegram
оставляет секрет без изменений; очистка выполняется отдельным подтверждаемым
действием. Токен API не возвращает. Защитите файл настройками доступа ОС:
секрет хранится на сервере, не в браузерном хранилище.

`/debug` обновляет состояние каждые 5 секунд в видимой вкладке; при обрыве
показывает устаревшие данные и повторное обновление. Отказ отдельного модуля
не скрывает остальные. `GET /api/debug/status`, `/api/debug/events`
(`after`, максимум `limit=100`) и `/api/debug/export` содержат только
разрешённые диагностические поля. До 200 событий текущего запуска хранятся
в памяти уже как безопасные коды, без исходных исключений, токенов,
заголовков авторизации, адресов потоков и аргументов процессов.
Успешная проверка CGI не означает готовность автоматического учёта.
Оба способа запуска — `python main.py` и `python -m uvicorn main:app` —
сохраняют эту обработку логов. Журнал HTTP сохраняет метод, путь и код ответа,
но не параметры запроса или заголовки с секретами.

## Telegram-уведомления

`TELEGRAM_NOTIFY_PRESENCE` управляет текстовыми уведомлениями о подтверждённых
событиях входа/выхода. Это не сообщения о каждом появлении человека в кадре
и не подтверждение полноты рабочего дня.

Уведомления о переходах между камерами — текст с подтверждённым `G#`, номерами
камер и оценкой связывания (`TELEGRAM_NOTIFY_GLOBAL_TRANSITION=true`). Они
публикуются только после атомарного сохранения связи, не удостоверяют личность
сотрудника. Оповещение о новом глобальном ID выключено по умолчанию
(`TELEGRAM_NOTIFY_GLOBAL_NEW`).

### Настройка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Добавьте бота в группу.
3. Предпочтительно задайте явный `TELEGRAM_CHAT_ID`. Для автоопределения
   отправьте в нужной группе `/start`; может быть выбран и личный чат.
4. Заполните `.env`:

```env
TELEGRAM_BOT_TOKEN=1234567890:AA...
TELEGRAM_CHAT_ID=          # можно оставить пустым — определится по /start
TELEGRAM_NOTIFY_PRESENCE=true
```

Если `TELEGRAM_CHAT_ID` пуст, приложение само опрашивает getUpdates, пока
не появится `/start`, и сохраняет chat_id в `data/telegram_chat_id.txt`.
Отправка идёт через фоновую очередь (до 200 сообщений, три попытки);
доставка не гарантируется, возможны потери. Нужен HTTPS к `api.telegram.org`.
Уведомления с изображениями передают персональные данные за пределы компьютера.

## Журнал людей и калибровка сцены

Каждый принятый реальный трек получает локальный визит, даже если лицо, тело или
снимок недоступны. Первое наблюдение сохраняется как предварительное; ссылка UUID
появляется в живой рамке только после подтверждения записи. Источник, поток,
поколение трекера и версии галереи/калибровки проверяются перед публикацией.
Смена источника или перезапуск не продолжает старые ID.

`JOURNAL_DEGRADED` означает, что полнота журнала не гарантирована. Принятые команды
ожидают восстановления; насыщенное поколение закрывается с `JOURNAL_GAP`, затем
трекер получает новое поколение. Закрытие процесса сообщает о несохранённом остатке,
а не выдаёт его за успешную запись. Камеру с историей или ожидающими командами
нужно выключать, не удалять.

`JOURNAL_IMAGE_KEEP_DAYS=30` (1–365, настройка следующего запуска) относится только
к изображениям новых визитов. Почасовая очистка работает и при выключенном live AI;
UUID, события и метаданные остаются. Фото сотрудников и старый межкамерный архив
этой политикой не удаляются. В карточке визита оператор может вручную выбрать
сотрудника и добавить именно показанный, пригодный и неистёкший образец лица.
Существующие фото не заменяются; предел — 15. Автоматического самообучения нет.

На странице камеры зафиксируйте исходный кадр. Доступны вершины мышью, стрелками
и точными координатами, отмена/повтор, масштаб и сдвиг. До двух кадров на установку,
срок 300 с. Истечение кадра запрещает дальнейшее сохранение/принятие подсказок,
но не отменяет ранее сохранённый масштаб неизменившейся камеры.

MobileSAM работает только на CPU по выбранным оператором точкам/рамке. Пунктирный
кандидат нужно принять в черновик и отдельно сохранить. Несвязные, дырявые и
непригодные маски могут не дать контура; ручная разметка остаётся доступна.
Модель не восстанавливает скрытый за мебелью пол и не задаёт названия объектов.

Для метров нужны четыре упорядоченных угла реального плоского прямоугольника и
**измеренные** ширина/глубина. Сетка и вид сверху — приближение; размеры кадра
не являются метрами. Силуэт предмета не исключает человека из журнала; при
неопределённой точке стопы метры не показываются. Сцена и линия входа сохраняются
раздельно. Изменение сцены не вводит учёт в эксплуатацию; изменение входа требует
повторной наладки. После изменения источника разметка остаётся как устаревшая:
новый кадр и явная сверка черновика обязательны. Физический сдвиг камеры при том же
потоке автоматически не обнаруживается.

## Межкамерный трекинг (Multi-Camera Person Tracking)

Система пытается сопоставить человека между камерами и сохранить `global_id`.
Совпадение не гарантировано; локальный `track_id` остаётся per-camera.

```text
CAM-01 → track_id=17 ─┐
                     ├→ global_id=184      (Person Re-ID OSNet + composite score)
CAM-02 → track_id=42 ─┘
```

Необязательный слой получает готовые 512-мерные OSNet AIN x1.0-векторы после
приоритетной обработки учёта. На один вызов — до 16 тел; отложено не более
128 уменьшенных кадровых вырезок, с чередованием камер. Исходные кадры в этой
очереди не удерживаются.

Кандидат оценивается по внешности, времени, направленной топологии, пропорциям
и только свежему подтверждённому лицу. Разные подтверждённые сотрудники — veto;
неоднозначность не превращается в уверенное присвоение личности. Связь визита,
`GlobalPerson` и событие `LINKED` сохраняются одной транзакцией. До подтверждения
БД ни ID, ни вектор не попадают в живую галерею. Тело никогда не назначает
сотрудника визиту и не создаёт рабочий интервал.

Старые `/global/{id}`, события и снимки остаются архивом. После перезапуска
живая галерея пуста: старые векторы не сравниваются с новой моделью. Новые ID
выдаёт БД при сохранении связи; архивные записи не переписываются.
`GLOBAL_GALLERY_TTL` очищает память, не историю. Возрастного удаления старого
межкамерного архива нет; контролируйте размер БД.

`MULTI_CAMERA_TRACKING_ENABLED=false` отключает только необязательный глобальный
слой. Отладка: `MC_DEBUG=true` включает его подробные сообщения.

### Модель Re-ID

Используется только компонент `body` проверенного набора `AI_MODEL_MANIFEST`:
OSNet AIN x1.0 автора, RGB 256×128, нормированные 512-векторы. Старый `REID_MODEL`
не выбирает веса. Отсутствие компонента отключает только связывание по внешности,
а не локальный трек человека. Внешность никогда не присваивает сотрудника для учёта.

### Топология камер

Адаптируйте `topology.json.example` под **ID камер приложения**, задайте
`TOPOLOGY_CONFIG=topology.json` и перезапустите. Само наличие файла ничего
не включает. Без него остаются остальные сигналы сопоставления с нейтральным
вкладом топологии. Неуказанные направленные переходы не блокируются.
Топология не задаёт разметку проходов или правила расчёта рабочих часов.

## Как работает распознавание

D-FINE-S находит кандидатов людей; локальный трекер использует движение
`(cx,cy,a,h,vx,vy,va,vh)` по времени получения кадров и Hungarian-сопоставление,
сначала сильных, затем слабых детекций. Неоднозначные связи изолируются;
неоднозначность очищает личность; завершение трека удаляет её. Предсказанные рамки
не продлевают видимость и не создают проходы. Обычный режим требует качественного
нативного лица, сходства ≥.60, отрыва ≥.10 и трёх разных наблюдений за 2 с.
Глобальный архив Re-ID отделён от галереи внешности сотрудников текущего дня.

**Текущий учёт** использует реальные появления сотрудников на камерах с переключателем
«Учёт времени». Лицо подтверждает личность трека; галерея внешности может перенести
её на другую камеру в тот же день. «День идёт» и «Итог дня» используют разные
допустимые промежутки, а необязательные проходы уточняют короткие выходы.
Старый legacy-архив присутствия и API событий удалены вместе с прежней историей
при обновлении attendance-v3 после резервного копирования.
[Правила расчёта, корректировки и ограничения](ATTENDANCE.md).

## Конфигурация

Шаблон развёртывания — `.env.example`; приоритет:
**окружение → операторский JSON → .env → defaults**. Значения читаются при
запуске, не на лету. Пример (встроенный `APP_HOST` по умолчанию — `0.0.0.0`;
для доступа только с этого компьютера используйте `127.0.0.1`):

```env
APP_HOST=127.0.0.1
APP_PORT=8000

RTSP_CONNECT_TIMEOUT=10
RTSP_RECONNECT_MAX_DELAY=30
DEFAULT_RTSP_PORT=554
PREVIEW_FPS=10
STREAM_OUTPUT_FPS=15
STREAM_HWACCEL=auto            # auto | cuda | none; только auto допускает один fallback

# AI
AI_ENABLED=true
AI_FPS=5                      # кадров/сек на камеру для AI
AI_DEVICE=auto                # auto | cpu | cuda
AI_BATCH_SIZE=4               # 1–8 разных камер
AI_BATCH_WAIT_MS=10            # не позже ближайшего срока
PERSON_CONFIDENCE=0.1
TRACK_LOST_TIMEOUT=3
MIN_RECOGNITION_CONFIDENCE=0.60
MIN_CONFIRMATIONS=3
FACE_RECOGNITION_RETRY_INTERVAL=0.5
LIVE_FACE_MIN_SIZE=48
LIVE_FACE_MARGIN=0.10
LIVE_FACE_WINDOW=2.0
LIVE_FACE_RECHECK_INTERVAL=2.0
FACE_MIN_SIZE=80
CUDA_DLL_PATH=                # путь к CUDA/cuDNN DLL (пусто = авто-поиск)

# Telegram
TELEGRAM_BOT_TOKEN=            # токен от @BotFather
TELEGRAM_CHAT_ID=              # пусто = авто-определение по /start в группе

# Межкамерный трекинг

```

Пароли камер хранятся в SQLite, не в .env; через API не отдаются.

## Проверка подключения к Dahua вручную

Предпочтительна проверка в интерфейсе. Если используете ffprobe вручную,
помните: URL с реквизитами может остаться в истории команд и быть виден
другим пользователям ОС в аргументах процесса. Пример с условными реквизитами:

```bash
ffprobe -v error -rtsp_transport tcp -select_streams v:0 \
  -show_entries stream=codec_name,width,height,avg_frame_rate \
  -of json "rtsp://USER:ENCODED_PASSWORD@192.0.2.10:554/cam/realmonitor?channel=1&subtype=0"
```

## curl-примеры

Все POST/PUT/DELETE и другие изменяющие запросы отправляйте с
`X-Operator-Request: 1`; при наличии `Origin` используйте origin приложения.
Запускайте примеры только в доверенной среде. Не помещайте реальные секреты
в общие скрипты/историю команд. Для нестандартного порта замените `8000`.

```bash
# Камеры
curl http://localhost:8000/api/cameras
curl -X POST http://localhost:8000/api/cameras/1/test -H "X-Operator-Request: 1"
curl http://localhost:8000/api/cameras/1/status
curl http://localhost:8000/api/cameras/1/detections     # текущие люди (треки)
curl -m 3 http://localhost:8000/api/cameras/1/stream -o stream.bin

# CGI-обнаружение; отсутствие разрешения не мешает ручному вводу каналов.
curl -X POST http://localhost:8000/api/cameras/discover \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"nvr_host":"192.168.1.100","username":"admin","password":"CHANGE_ME","http_scheme":"http","http_port":80}'

# Атомарное добавление выбранных каналов; enabled=false оставляет их выключенными.
curl -X POST http://localhost:8000/api/cameras/batch \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"request_id":"3812999c-6f14-4567-ad17-6bdc4078f3b1","nvr_host":"192.168.1.100","rtsp_port":554,"username":"admin","password":"CHANGE_ME","archive":{"http_scheme":"http","http_port":80,"utc_offset_minutes":180},"channels":[{"channel":1,"name":"Вход","stream_type":"main","enabled":false},{"channel":2,"name":"Склад","stream_type":"sub","enabled":false}]}'

# Первичная настройка только если последний GET /api/cameras/1 вернул archive:null.
# Явный null означает отсутствие настроек; успешное создание даёт ревизию 0.
curl -X PUT http://localhost:8000/api/cameras/1 \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"password":"","expected_archive_revision":null,"archive":{"http_scheme":"http","http_port":80,"utc_offset_minutes":180}}'

# Изменение существующих настроек, если последний GET вернул archive.revision:0.
# Пустой пароль не меняет секрет; 0 не заменяет null при отсутствии настроек.
curl -X PUT http://localhost:8000/api/cameras/1 \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"password":"","expected_archive_revision":0,"archive":{"http_scheme":"https","http_port":443,"utc_offset_minutes":180}}'

# Рабочие места — необязательные метки
curl http://localhost:8000/api/workplaces
curl -X POST http://localhost:8000/api/workplaces \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"name":"Магазин №1"}'

# Сотрудники: metadata + 1–15 файлов в одном multipart-запросе
curl http://localhost:8000/api/employees
curl -X POST http://localhost:8000/api/employees -H "X-Operator-Request: 1" \
  -F 'metadata={"first_name":"Иван","last_name":"Петров","external_id":"10023","workplace_ids":[],"request_id":"67e149b7-70f0-4fe5-b2c9-566503591416"}' \
  -F "files=@photo1.jpg" -F "files=@photo2.jpg"
curl "http://localhost:8000/api/employees/1?faces=true"

# Полная замена: keep_face_ids содержит только оставляемые ID из ответа GET.
# Здесь прежние фото заменяются одним новым; expected_revision берётся из GET.
curl -X PUT http://localhost:8000/api/employees/1/faces -H "X-Operator-Request: 1" \
  -F 'metadata={"expected_revision":1,"keep_face_ids":[]}' -F "files=@replacement.jpg"

# Данные: ревизия после предыдущего сохранения; [] снимает все метки.
curl -X PUT http://localhost:8000/api/employees/1 \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"expected_revision":2,"first_name":"Иван","last_name":"Петров","workplace_ids":[]}'

# Переименование/архивирование места не удаляет существующие назначения.
curl -X PUT http://localhost:8000/api/workplaces/1 \
  -H "X-Operator-Request: 1" -H "Content-Type: application/json" \
  -d '{"name":"Магазин №1 — архив","active":false}'

# Текущий учёт рабочего времени
curl http://localhost:8000/api/attendance/status
curl http://localhost:8000/api/attendance/active
curl "http://localhost:8000/api/attendance/report?from_date=2026-11-01&to_date=2026-11-18&employee_id=1"

# Межкамерный трекинг
curl http://localhost:8000/api/global-persons
curl "http://localhost:8000/api/global-persons?status=ACTIVE&search=184"
curl http://localhost:8000/api/global-persons/1
curl http://localhost:8000/api/global-persons/1/photo          # последний снимок
curl http://localhost:8000/api/global-persons/1/timeline
curl http://localhost:8000/api/global-persons/1/trajectory
curl http://localhost:8000/api/global-persons/1/observations
curl http://localhost:8000/api/cameras/1/tracks
```

В примерах замените ID и `expected_revision` фактическими значениями из ответа;
для нового создания используйте новый UUID. Повтор создания с тем же UUID,
нормализованными данными и теми же файлами в том же порядке возвращает исходный
результат, даже если AI позже недоступен. Иное содержимое с тем же UUID — 409.
Ответ создания — 201 с `revision`, `faces`, `faces_count`, `workplaces` и признаками
`needs_name_completion` / `needs_photo_remediation`.

JPEG/PNG должны быть неподвижными: максимум 15 МиБ и 20 миллионов пикселей на
файл, 15 файлов, 64 КиБ для JSON `metadata`, 226 МиБ для всего запроса.
Ошибка проверки фото возвращает 422:
`{"detail":{"code":"PHOTO_VALIDATION_FAILED","committed":false,"files":[{"index":0,"filename":"photo.jpg","error":"…"}]}}`.
При 409 карточка изменилась: загрузите текущую версию, проверьте сохранённый
черновик и повторите сохранение. Старые JSON-создание без фото,
`POST /api/employees/{id}/faces` и удаление отдельного фото больше не поддерживаются;
используйте атомарный `PUT` итогового набора (1–15 фото, новые файлы необязательны).

`POST /api/cameras` остаётся самостоятельным созданием одной камеры;
`POST /api/cameras/batch` принимает 1–64 уникальных канала и возвращает 201
`{"cameras":[...]}`. Один UUID `request_id` и те же нормализованные данные
в том же порядке повторяют исходный результат без новых строк/ридеров;
другие данные или операция с этим UUID — 409. Повтор уже добавленного
источника (нормализованный адрес, RTSP-порт, логин, канал, поток) в пакете —
409 без частичного сохранения. Пароли не сохраняются в журнале повторов.
`POST /api/cameras/discover` возвращает `channels`, отдельный флаг
`capabilities.channel_titles` и `error_code`: ошибка доступа/тайм-аут/
неподдерживаемый CGI не подменяются успешным пустым результатом. Для проверки
сохранённого пароля можно передать `camera_id` вместо нового пароля,
сохранив остальные поля подключения.
При изменении `archive` поле `expected_archive_revision` обязательно:
если последний GET вернул `archive:null`, передайте явный `null`;
иначе — целое `archive.revision`, включая 0. Отсутствие поля — 422.
Новые настройки получают ревизию 0. Несовпадение состояния/ревизии — 409
без сохранения любых полей камеры, включая одновременно изменённое RTSP-подключение.
Загрузите текущую версию и повторно примените проверенный черновик.
Первичная настройка внутри `POST /api/cameras` или `/batch` не требует этого токена.

## Безопасность

- Пароли камер и токены не возвращаются в диагностике и не попадают в HTML/JS.
  Адреса с реквизитами, секреты и контекст исключений удаляются из серверных логов.
- Исходные фотографии сотрудников не сохраняются; сохраняются эмбеддинги
  и миниатюры 112×112. Отдельно хранятся доказательства проходов, снимки/эмбеддинги
  глобальных наблюдений, история и явно запрошенное локальное видео.
- В логах нет изображений и эмбеддингов.
- Аутентификации нет: только localhost или ограниченная firewall доверенная
  LAN/VPN, **никакой публичной публикации**. Операторская подпись не проверяет личность.
- Во всех изменяющих API-запросах, включая запись/просмотр, настройки,
  проверки и обнаружение камер, передавайте `X-Operator-Request: 1`.
  Если есть `Origin`, он должен совпадать с origin приложения. Это не пароль
  и не аутентификация. Перенос настройки дополнительно разрешён только локально.
- Пароли камер хранятся в SQLite, токен Telegram — в окружении/файлах настроек.
  Защитите ACL ОС для данных, моделей, конфигурации, журналов и резервных копий.
  RTSP не является TLS; защита реквизитов в ответах не шифрует их на диске/в сети.

## Производительность

- Один владелец AI обслуживает все камеры; несколько процессов/uvicorn workers
  не поддерживаются. Пакеты содержат разные камеры, по умолчанию до четырёх;
  пропущенные сроки не превращаются в очередь повторных обработок.
- Декодер выдаёт до `STREAM_OUTPUT_FPS=15` нативных кадров/с без синтеза
  недостающих кадров. `STREAM_HWACCEL=auto` пробует CUDA и допускает один
  программный запуск только при фактической ошибке аппаратной инициализации;
  явный `cuda` не переключается молча на CPU.
- Сетка получает JPEG до 480 px, подробное превью до 1280 px; обычный snapshot
  остаётся нативным. Общий кеш хранит только две последние производные на камеру.
- `AI_FPS=5` и `ATTENDANCE_AI_FPS=10` — цели, не гарантии. Отключение учёта
  не отключает общее распознавание камеры. Проверяйте отдельные FPS анализа,
  задержку p95 за 60 с, пропуски, отложенные задачи и фактический декодер в `/debug`.
  `CAPACITY_DEGRADED` появляется после 10 с ниже 90% цели или p95 > 1 с
  и снимается после 10 с здоровой работы. ONLINE описывает соединение, не анализ.
  История измерений переживает переподключение и ошибки модели; удаляется только
  при исключении камеры из анализа. Пропущенные исходные кадры считаются по
  последовательности внутри одного потока отдельно от пропущенных сроков.
- При одинаковом сроке первыми обрабатываются камеры учёта, затем действует
  вращение остальных камер: иначе большой общий пакет может вытеснить следующий
  100-мс срок учёта. Отключённые потоки и паузы повтора не создают активный опрос.

## Резервное копирование и сохранность истории

Остановите обёртку автозапуска, сервер и все процессы приложения. Для SQLite
не копируйте один `.db` у работающего приложения: зафиксированные данные могут
оставаться в `-wal`. Используйте согласованную SQLite backup-процедуру либо
после остановки сохраните весь комплект БД и оставшихся `-wal`/`-shm` вместе.
Не удаляйте WAL вручную. Проверьте восстановление на отдельной копии установки.

Сохраняйте фактический путь из `DATABASE_URL`, `data/`, `.env`, операторский файл
(включая внешний `OPERATOR_SETTINGS_PATH`), модели и используемую топологию.
Для восстановления видео нужен **весь** `RECORDING_ROOT`, в том числе если
он вне `data/`: один индекс/БД не восстанавливает медиафайлы. Миграционная
копия схемы не заменяет регулярную резервную копию всей установки.
`.nmsetup` ниже переносит только настройку, не историю, видео или конфигурацию запуска.

Сотрудники и камеры с историей защищены от удаления (409): отключайте их,
не удаляя записи вручную из БД. Архивирование рабочего места сохраняет связи.
Глобальная/legacy-история не очищается автоматически по возрасту; срок хранения
JPEG-доказательств учёта и лимиты видео — отдельные политики.

## Перенос настройки на другой компьютер (без видео)

На обоих компьютерах установите одинаковую версию приложения и зависимостей
(`cryptography>=46` включён в requirements.txt). Перенос v2 проверяет объявленный
`face_model_id` и фактическое происхождение каждого образца, не имя пакета.
V1 читается только как миграция данных: пригодные выровненные фотографии пересчитываются
целевым распознавателем; неподходящие сохраняются как непригодные. Файлы моделей
не входят в перенос. Сцены импортируются как требующие проверки, а не текущая калибровка.

1. На исходном компьютере откройте `http://localhost:8000/settings` непосредственно
   на сервере приложения (можно через удалённый рабочий стол).
2. В разделе **Перенос на другой компьютер** задайте уникальную парольную фразу
   (12–1024 байта UTF-8), повторите её и скачайте `.nmsetup`.
3. Передайте зашифрованный файл на новый компьютер; пароль храните отдельно.
   Максимальный размер — 64 МиБ. Забытый пароль восстановить нельзя.
4. На новом компьютере запустите приложение с **пустой базой**, откройте тот же
   раздел через localhost, выберите файл, введите пароль и нажмите **Проверить файл**.
5. Сверьте количество объектов и подтвердите импорт. В существующую непустую базу
   импорт запрещён: слияния и перезаписи нет. При обрыве ответа повторите
   подтверждение с тем же файлом и паролем, не очищая форму.
6. Обычным способом перезапустите приложение. Включённые камеры восстановятся,
   ручная запись сама не включится. Проверьте калибровку и повторно выполните ввод
   учёта в эксплуатацию: его разрешения не копируются.

Переносятся камеры с логинами/паролями, подключения к архивам, геометрия
калибровки (учёт выключен), рабочие места и связи с сотрудниками, карточки
сотрудников, сохранённые миниатюры лиц и эмбеддинги. Исходные загруженные
фотографии приложение не хранит. Старые неполные карточки сохраняются для исправления.

**Не переносятся:** видео, метаданные записей и кеш просмотра, история рабочего
времени/наблюдений и её изображения, настройки приложения/.env/Telegram,
топология, модели и настройки Cloudflare/WARP. VPN и маршруты до регистраторов
нужно настроить на новом компьютере отдельно. Это перенос настройки, а не полная
резервная копия. Экспорт и импорт через LAN, публичный адрес или прокси запрещены,
поскольку приложение не имеет встроенной аутентификации.
